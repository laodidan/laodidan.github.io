YouTube 视频下载流程（Windows + yt-dlp）

本文记录一套已经实际验证可用的 YouTube 视频下载流程，适用于 Windows、Firefox、yt-dlp 与 Deno 环境。当前环境下，默认优先使用 web_safari + HLS/m3u8，以避开部分 DASH 高清流可能出现的 HTTP Error 403: Forbidden。

请仅下载自己有权保存的内容，并遵守 YouTube 服务条款、版权规定及所在地法律。

本流程已经完成 Deno 与 bgutil Provider 配置。日常下载时不需要重复安装。

二、核心结论

以后下载新视频时，按以下顺序操作：

  1. 使用 -F 查看当前视频的全部格式；
  2. 在格式列表中优先寻找 PROTO 为 m3u8 的 HLS 格式；
  3. 优先选择同时包含视频和音频的 1080p60 或 1080p30 格式；
  4. 记下该格式对应的 ID；
  5. 使用 -f 格式ID 正式下载。

需要特别注意：格式 ID 不是固定的。 某个视频的 301 可能代表 1080p60，另一个视频却可能没有 301，因此每个新视频都应先运行一次 -F。

四、为什么优先选择 HLS/m3u8

格式 主要特征 结果

399 1080p60，AV1，DASH，纯视频 立即返回 403
301 1080p60，H.264 + AAC，HLS/m3u8 可以正常下载

五、常见问题处理

1. 出现 HTTP Error 403: Forbidden

先检查所选格式是否属于以下类型：

  • video only；
  • mp4_dash；
  • webm_dash；
  • 类似 299、399 的分离式高清视频流。

如果是，不要继续反复尝试同一 DASH 格式。重新运行查看格式命令：

然后改选 PROTO 为 m3u8 的格式。

如果 HLS/m3u8 也返回 403，可依次检查：

  1. Firefox 是否仍处于 YouTube 登录状态；
  2. 目标视频能否在 Firefox 中播放；
  3. 关闭 Firefox 后重新读取 Cookie；
  4. 更新 yt-dlp；
  5. 更换网络或代理节点后再次测试。

6. 出现 127.0.0.1:4416 警告

可能看到：

这通常表示 bgutil 插件尝试访问未启动的本地 HTTP Provider。若后续自动切换到 script-deno，并且格式读取或视频下载能够继续，则该警告本身不需要单独处理。

判断重点不是警告是否出现，而是后续是否出现成功信息或下载进度。若命令最终失败，仍应根据最后一段错误日志继续排查。

八、最终复核结论

  1. 301 不是固定的 1080p 格式编号，每个新视频都必须先运行 -F。
  2. 不能把所有 403 都归因于缺少 PO Token；本次环境中 Token 已成功生成，但部分 DASH 高清流仍返回 403。
  3. 本机当前经过实测的稳定方案是 Firefox Cookie + web_safari + HLS/m3u8。
  4. 299、399 等 DASH 纯视频格式不应作为当前环境的默认选择。
  5. Edge Cookie 在本机存在 DPAPI 问题，Firefox 是已经验证可用的方案。
  6. Deno、bgutil 和 FFmpeg 应继续保留，但不需要每次下载前重新安装。
  7. 日常操作只需记住两步：先用 -F 查看格式，再用 -f 格式ID 下载。
